Replaces the separate Claude Project, Codex Project and Cursor Project keys. Those still work but are marked (legacy) and will be removed in a later release — hold this key while that agent is frontmost to move it over, then delete the old key.
One key for Claude Code, Codex CLI, or Cursor CLI. Cursor here means the terminal agent — the cursor-agent command you run in iTerm2 or tmux. This key does not drive the Cursor editor, and Codex Desktop and non-interactive codex exec jobs are not targets either. Hold it for ½ second while the agent’s terminal is frontmost: the key works out which of the three it is looking at, stores that with the project, and takes on that agent’s mark — a coral spark for Claude, a violet square for Codex, an arrow for Cursor. Press to raise its terminal window and, under tmux, select its exact pane.

Blue with a moving dot means a turn is running, amber means the agent is waiting on you, white means the prompt is idle, and gray means the state is unknown or more than one session matches. The bar lights when your keystrokes would reach that exact session.

The red stripe is an unread mark. It appears when the agent finishes a turn while you are looking somewhere else, and it clears when you press the key (on a raise that actually succeeds — if raising the window fails, the key shows its alert and the mark stays) or on the first check that finds you already at that session. The key also alerts without raising anything when a press is ignored: all the focus keys share one raise at a time, so pressing while another is still going flashes and does nothing, leaving the mark alone. What it claims is narrow, on purpose: the most recent finished turn has not been seen. Starting a new turn clears it — the key goes back to blue and marks again when that turn ends. It needs the plugin watching to see the transition at all, so a plugin restart, or switching Stream Deck pages and back, forgets a pending mark rather than inventing one it never observed. It also samples every 2½ seconds, so a turn that starts and finishes inside one gap is never seen running and leaves no mark — the mark reports turns this key watched run, not every turn that happened. Focus this key cannot see — another machine attached to the same tmux session over ssh — cannot clear it either.

Requires: Automation access for iTerm2 and/or Terminal for the hot indicator, capture, and focusing (macOS prompts on first use). Finding sessions and reading their state needs no permission.

What amber can and cannot see. Codex records “waiting for your approval” in its own session log, so amber works for Codex in any terminal. Claude Code and Cursor write nothing that distinguishes it from ordinary work — the only evidence is the prompt on screen, which this key can read for tmux-hosted sessions only. In a bare iTerm2 or Terminal window those two show a waiting prompt as blue (running). For Claude that means two different prompts: a tool approval, and a question awaiting your decision — the question being the one you meet most, since approvals auto-accept under --permission-mode auto. Claude's plan-approval prompt appears to use the same component and so should behave the same way, but that was inferred from the CLI binary, never measured against a live plan prompt. Detection is deliberately narrow, so a future release of either tool that rewords its prompt makes amber stop appearing rather than start lying — though recognised prompt wording appearing in ordinary output can still, in principle, read as amber.

Codex and Cursor bind to one exact session, so two sessions in one folder are never confused. Claude Code has no session identifier and binds by project folder, so two Claude sessions in the same folder read as ambiguous (gray) rather than being guessed between.
